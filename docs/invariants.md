## Why JSON Instead of Hand-Written Markdown

The legacy Markdown table had three structural flaws that prevented machine verification:

1. **Colliding IDs**: two modules both claimed the same theorem range, making cross-file diffing impossible;
2. **Range notation**: tokens like `INV-12~16` cannot be subtracted mechanically;
3. **Ditto cells**: multiple invariants sharing a single test path obscured individual coverage.

The JSON registry requires a unique `id`, source file `source`, `symbol`, and single `test` path
so uncovered logic can be computed systematically.

## Validation Rules

| Rule | Outcome |
|---|---|
| `id` unique and matches `INV-<AREA>-<NN>` | FAIL on violation |
| `test` is a single existing file path | FAIL on violation |
| `test` contains `fc.assert` | FAIL on violation |
| `source` is an existing source file path | FAIL on violation |
| `source` + `symbol` pair is unique | FAIL on violation |
